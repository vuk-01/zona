# Backend tests

- Two layers, two folders (ADR-011):
  - `tests/unit/test_<name>_api.py`: the HTTP layer with the service mocked (`create_autospec(I<Name>Service, instance=True)` registered with `add_to_di_container`, removed with `remove_from_di_container`); routing, validation, auth, status codes and the error shape, no database
  - `tests/unit/test_<name>_service.py`: the service with its repositories and other domains' Protocols mocked (`create_autospec(I<Name>Repository, instance=True)`, passed to the constructor); the order of the checks, the roles and how a refused write is read, no database
  - `tests/integration/test_<name>.py`: the whole stack against a real temporary SQLite database (or `DATABASE_URL` from the environment); records are created through the API
- Shared fixtures only in `conftest.py` files: `client` (`tests/conftest.py`), `session_factory` + `auth_service` + one mocked service per domain (`listing_service`, `space_service`, `user_service`, `favorite_service`, `booking_service`) (`tests/unit/conftest.py`), `tables` + `clean_tables` + `auth_headers` + `other_auth_headers` + `host_auth_headers` + `space_id` + `listing_id` (`tests/integration/conftest.py`); a fixture used by one module stays in that module (`booking_id` in `test_bookings.py`)
- Every endpoint has at least: the happy path, unauthenticated (`401`) for writes, forbidden (`403`) where there is an owner, not found (`404`) where there is an id, validation (`422`) where there is input (`/test-endpoint` writes the set)
- Assert on the status code and on the error shape: `response.json() == {"detail": ..., "code": ...}`, or the exact `fieldErrors` keys for `422` (ADR-005)
- Assert that responses use camelCase keys (`imageUrl`, `createdAt`), not snake_case (ADR-010)
- A unit test asserts what the endpoint passed to the service (`listing_service.create.call_args.kwargs["current_user"].id == 1`), not what the service would have done
- In integration tests, create records through the API, not by inserting rows directly; every test starts from empty tables (`clean_tables`) and does not depend on another test or on `data/app.db`
- No `time.sleep`, no network, no real files: a test runs in milliseconds and offline; the one bounded wait allowed is `Event.wait(timeout)` in a concurrency test that proves a thread is still blocked in the database (below)
- "Now" comes only from `IClock`: tests that depend on the time register `FixedClock` (`tests/utils.py`) with `add_to_di_container(IClock, ...)` in an autouse fixture of the module, removed after the test (`set_now` in `test_bookings.py` also lets a test move the clock), including DST dates (ADR-022)
- A test for a row changed mid-request (deleted over a second connection, a status changed between the read and the compare-and-set) is proven once by making it fail: temporarily put back the code it guards against (`get_by_id` instead of `exists`, no re-read), run the test and see it fail, then restore the fix and see it pass; the temporary change is never committed (ADR-019, ADR-023)
- A lock is proven by a concurrency test (`tests/integration/test_<name>_concurrency.py`), not by reading the code (ADR-023). A `threading.Barrier` only shows that threads reached the same line of Python, not that one is waiting in the database, so the test wraps the real lock method in a subclass of the real repository (`GatedSpaceRepository`): thread A takes the lock, sets an `Event` and holds the transaction open until released; every other thread sets its own `Event` right before calling the real lock method and another one after it returns; the test waits for the first `Event`s, asserts that none of the second ones fires within `BLOCKED_FOR = 0.3` seconds (those threads are blocked in the database), then releases A and asserts the outcome (`[200, 409]` for a whole space, `[200, 200, 409]` for two desks) and the confirmed rows in the database. Every other wait is bounded (`TIMEOUT = 5.0`), so a broken lock fails the test instead of hanging it. A control test must overbook: the lock is replaced by a plain read that finds the space and locks nothing (`NoLockSpaceRepository`), and a `Barrier` after the count (`CountTogetherBookingRepository`) makes both confirms count before either writes; a `Barrier` is enough there, because only the order of the reads in Python matters. The same file runs on SQLite and on Postgres through `DATABASE_URL`
- A lock that protects a delete against a new child row is proven by the pair that can lose a row, not only by the pair that shares the lock (`tests/integration/test_spaces_concurrency.py`): POST ↔ DELETE in both orders (DELETE first: the POST's INSERT waits, then `POST 404` + `DELETE 204`; POST first: `POST 201` + `DELETE 409` with the booking still there), and a control where `lock` is a plain read (`NoLockSpaceRepository`) and DELETE waits after its count (`after_count`) until a POST has answered `201`: it must end `201` + `204` with the booking gone. A pair whose answer is the same without the lock (confirm ↔ DELETE: a pending booking is already active) proves only the wait, and its control asserts that the other request gets through within `BLOCKED_FOR`; say so in the test, never claim more. An assertion that depends on the engine says which and why (`delete_got_through is is_sqlite`), it is not dropped (ADR-025, ADR-026)
- An N+1 test counts the statements (`event.listen(engine, "before_cursor_execute", ...)`) for a page of one item and of several, built from different rows: every list item has its own related rows and its own numbers (`test_host_list_counts_bookings_in_the_same_queries_for_any_number_of_spaces`: three spaces, each with its own guest and different `availableDesks` and `bookingCounts`, read with `size=1` and `size=3`); it asserts the numbers per item too, and is proven once by putting a query per item back and seeing it fail (`.claude/frequent-mistakes.md`, ADR-027)
- Test names say what is expected: `test_patch_by_other_user_is_403`, not `test_patch_2`
- Every test function is typed (`-> None`, fixtures annotated); mypy checks `tests/` too
- A test is never deleted or skipped to make the suite green; a failing test is a finding
